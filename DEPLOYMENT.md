# VINNER Deployment Notes

## Production Stack

- Frontend: Astro
- Hosting and serverless backend: EdgeOne Pages
- CMS: Decap CMS editing JSON content in GitHub
- Email delivery: Resend
- Lead storage: Feishu Bitable
- Optional instant alert: Feishu Bot Webhook

## Deploy to EdgeOne Pages

1. Push this project to GitHub.
2. Import the GitHub repository in EdgeOne Pages.
3. Use these EdgeOne Pages settings:
   - Framework Preset: Astro
   - Build Command: `npm run build`
   - Build Output: use the `.edgeone` output generated by `@edgeone/astro` (do not publish the repository root)
4. Add the environment variables from `.env.example`.
5. Deploy.

## Contact Form Environment Variables

Required for email delivery through Resend:

```text
RESEND_API_KEY=
CONTACT_FROM=VINNER Website <noreply@vinnercare.cn>
CONTACT_TO=hongzihao@vinnercare.cn
```

Resend's free plan can be used for initial testing. Create an API key in Resend and add it to `RESEND_API_KEY`. The `onboarding@resend.dev` sender is intended for testing and may only deliver to the email address associated with the Resend account. For production delivery to any recipient, verify `vinnercare.cn` in Resend and change `CONTACT_FROM` to a verified sender such as `VINNER Website <noreply@vinnercare.cn>`.

Required for Feishu Bitable storage:

```text
FEISHU_APP_ID=
FEISHU_APP_SECRET=
FEISHU_BITABLE_APP_TOKEN=
FEISHU_BITABLE_TABLE_ID=
```

Optional for Feishu group notifications:

```text
FEISHU_WEBHOOK_URL=
```

## CMS Production Requirements

Decap CMS needs a GitHub repository and OAuth login. The repo is configured as:

```yaml
backend:
  name: github
  repo: zionhong5875-ai/VINNER
  branch: main
  site_domain: vinnercare.com
  base_url: https://vinnercare.com
  auth_endpoint: oauth
```

Then invite editors to the GitHub repository with limited write access. Editors use `/admin/` to change site settings, homepage content, product lines, SKUs, certificates, contacts, news, blogs, digital resources, images, and PDF downloads.

Create a GitHub OAuth App:

```text
Homepage URL: https://vinnercare.com
Authorization callback URL: https://vinnercare.com/oauth/callback
```

Add these EdgeOne Pages environment variables:

```text
OAUTH_GITHUB_CLIENT_ID=
OAUTH_GITHUB_CLIENT_SECRET=
```

## Production and preview indexing

The application uses `@edgeone/astro` and generates its deployment output in `.edgeone/`. No deployment-platform environment variable is required for indexing.

Configure these project variables in EdgeOne Pages:

```text
PUBLIC_SITE_URL=https://vinnercare.com
SITE_INDEXING_ENABLED=true
```

Only requests on the exact configured production host may be indexed. Localhost and temporary preview hostnames receive `noindex, nofollow` even when they share the project variables. Set `SITE_INDEXING_ENABLED=false` to block indexing deliberately. The optional `auto` mode enables indexing only when `PUBLIC_SITE_URL` is explicitly configured; the request-host check still applies.

After a successful deployment, verify `/robots.txt`, `/sitemap.xml`, a Chinese page, an English page, and a preview hostname. Confirm the official domain permits indexing, previews are blocked, and canonical/hreflang links use the official HTTPS domain.

### Sitemap and Google Search Console

`/sitemap.xml` is generated on every build from the current public content and canonical route mappings. Published products, articles and glossary terms automatically contribute both language versions; coming-soon products, operational endpoints and old redirect URLs are excluded. Existing files under `SEO审计/` are historical audit snapshots, not the deployment source.

The build checks sitemap coverage against static page files before compilation, then checks `dist/client/sitemap.xml` against current content after compilation. New static pages must also be registered in `src/utils/search-routes.mjs`; the build fails if either language is missing. URL changes must update their public slug mapping and preserve a 301 redirect from the previous address. `lastmod` is emitted only where an explicit, valid editorial update date is known; do not set all dates to deployment time.

Run `npm run check:sitemap` for source coverage, `npm run test:sitemap` for regression checks, and `npm run audit:crawl` against the local preview to verify every sitemap URL, canonical, trailing slash and legacy redirect. After production deployment, run:

```sh
AUDIT_BASE_URL=https://vinnercare.com AUDIT_EXPECT_INDEXING=true npm run audit:crawl
```

In the verified `vinnercare.com` Search Console property, submit `https://vinnercare.com/sitemap.xml` in the Sitemaps report. Submit the hosted URL rather than an old downloaded snapshot. Keep this address for future deployments: each new build replaces its contents, and production `robots.txt` advertises the same address.

## Local review

Run `npm run dev` for local previews. `npm run build` runs CMS content validation and the EdgeOne production build. For full page checks against a running preview, set `AUDIT_BASE_URL` and run `npm run audit:seo` and `npm run audit:crawl`. Local builds and previews do not publish changes.
